# DriverLens desktop — security boundary

Status: **in development** (record date 2026-10-08). Scope: the desktop edition (`desktop/`). Every statement below describes what the code in this repository actually enforces, with the test that covers it where one exists. For the product-level view see [DESKTOP.md](DESKTOP.md); for the E2E harness see [NATIVE-E2E.md](NATIVE-E2E.md).

## Command boundary

- **Exactly six IPC commands** — `scan_devices`, `get_scan_state`, `cancel_scan`, `open_report`, `export_report`, `get_report`. No other custom command exists.
- **Deny by default.** `desktop/src-tauri/build.rs` declares the six commands through Tauri's `AppManifest`, which switches the invoke path to *deny by default* and autogenerates one `allow-<command>` / `deny-<command>` permission pair per command (`permissions/autogenerated/`). A custom command runs only when a capability explicitly grants it.
- **Window-scoped.** `capabilities/default.json` grants the six `allow-*` permissions to the bundled `main` window only. Any other window, and any remote origin, is denied before the command body runs.
- **Narrow arguments.** `scan_devices`, `get_scan_state`, `cancel_scan`, `get_report` and `open_report` take **no arguments**. `export_report` takes exactly one optional argument — `ids: string[]`, a list of device digests validated against the current report and used only for set membership. The webview cannot supply an executable name, a shell command, a collector script path, or a filesystem destination.
- Covered by `tests/ipc_boundary.rs` (10 tests): an allowed command responds; an unknown command name is rejected; a window without the capability is denied for every command; a remote origin is denied; forged arguments cannot change program args or output; `get_report` ignores forged arguments; the boundary is independent of scan state. The native E2E run re-checks the denial through the real window ("unauthorized IPC" case).

## Collector spawn discipline

- **Direct spawn, no shell.** The collector is spawned with `Command::new(<pwsh>)` and a fixed six-element argument vector: `-NoProfile -NonInteractive -File <bundled script> -OutputPath <app-owned temp file>`. No `cmd /c`, no `sh -c`, no string concatenation, no per-scan overrides, and never `-ExecutionPolicy` (the script runs under the machine's policy).
- **Trusted executable resolution (fail closed).** In order: (1) `DRIVERLENS_POWERSHELL`, which must be an absolute path to an existing `pwsh.exe`/`powershell.exe` — an invalid value fails the scan with `executable_missing` rather than being silently ignored; (2) `%ProgramFiles%\PowerShell\7\pwsh.exe`; (3) a controlled full-path search of `PATH` (absolute entries only, no current-directory search). There is no generic-shell fallback. Environment-based selection is process-scope — a webview can never set it.
- **Process ownership.** Cancel and timeout call `kill` on exactly the owned child handle; no process enumeration happens anywhere. The script spawns no grandchildren (CIM/WMI queries run in-process), so killing the direct child is a complete kill — with a standing note to re-verify if the script ever gains child processes.
- **Limits and hygiene.** 120 s wall deadline; stdout/stderr drained continuously into 64 KiB rolling tails (a chatty child cannot deadlock on a full pipe); the report file is capped at 20 MiB before parsing; `CREATE_NO_WINDOW` so a GUI app never flashes a console. On app exit, the owned child is killed (never orphaned).

## Native dialogs — Rust side only

- `open_report` / `export_report` open the OS file pickers through the dialog plugin's **Rust API** (`TauriReportDialogs`). The webview holds **no dialog permission** — `capabilities/default.json` does not grant the dialog plugin — and the chosen path never travels through the webview. Only the parsed, validated report returns from import.
- Import filters `*.json`; validation (`report.rs`) runs before anything replaces the current report.
- Export writes the current in-memory report; the save dialog's own overwrite confirmation is the only overwrite confirmation; `ids` are validated against the report *before* the dialog opens (`invalid_selection` otherwise).

## Content Security Policy

- Production CSP (strict, from `tauri.conf.json`): `default-src 'self'; connect-src ipc: http://ipc.localhost; script-src 'self'; style-src 'self'`.
- A separate dev CSP (Vite HMR websocket + inline styles) keeps dev-only allowances out of production; the bundle test asserts the split.
- The frontend loads only local assets — no external subresources.

## Bundled resources only

- The bundle ships **exactly the collector script** (`resources/Collect-DriverLens.ps1`) plus icons — asserted by the bundle test.
- The bundled script is **byte-identical to the reviewed repository source** (sha256 `eb13430f4513427e41856d29824d85a6f501af2d2fbcb373fcde026991db7adb`, parity checked by test and by the launch verification).

## No telemetry, no network

- Comment-stripped static scan of `desktop/src/**`: zero `fetch`/XHR/WebSocket/EventSource/`sendBeacon`/serviceWorker/`importScripts`, zero external URL literals; the only `@tauri-apps` import is the IPC wrapper (`@tauri-apps/api/core`).
- At runtime the app opens **no HTTP port** (verified: no listener on the browser edition's port 8781 while the desktop app runs; its transport is Tauri IPC).
- Disclosure (installer): when the WebView2 runtime is missing, the installer's default bootstrapper downloads it — that step needs internet. The app itself never needs the network.

## Log sanitization

- Errors are **static**: the ten `ScanErrorCode` values (`busy`, `executable_missing`, `timeout`, `cancelled`, `exit_failure`, `output_missing`, `too_large`, `invalid_report`, `invalid_selection`, `io`) each carry a fixed message template. No report contents, device IDs, usernames, hostnames, or raw paths appear in any error.
- The bounded stdout/stderr tails stay in memory on the private scan-manager state and are **never serialized to the webview**. The collector module's production code contains no `println!`/`eprintln!` (the only occurrence in the file is inside a `#[test]`).
- Import rejection messages are static templates (an index only); a non-JSON file yields exactly "The selected file is not valid JSON."
- Sentinel-leak tests assert that a failed scan/import leaks nothing into snapshots or messages, and that stderr tails containing report-like content never reach the snapshot.

## Privacy limits (must not be overclaimed)

- The report is **local**: no upload, no telemetry.
- Device digests are a stable SHA-256 prefix of the uppercased device instance ID — **stable, pseudonymous, and linkable across exports/reports; they are not anonymity**. The same device carries the same digest in every report it appears in.
- Device names, provider strings, INF names and notes are free text and **may identify specific equipment**.
- No blanket "anonymous report" claim is made anywhere in the product or docs.

## Automation surface stays out of production

- The WebDriver E2E plugin (`tauri-plugin-wdio-webdriver`) is an **optional** dependency behind the `wdio-e2e` cargo feature; every reference is `#[cfg]`-gated and the E2E build uses a separate `CARGO_TARGET_DIR`. Default/release builds contain no WebDriver server, no fakes, and no environment hooks.
- Verified on the release binary: `cargo tree` shows no wdio crate in the default build, and a byte-level scan of the shipped `driverlens-desktop.exe` finds zero occurrences of `wdio`, `webdriver`, `e2e_harness` or `DRIVERLENS_E2E_*` (see [DESKTOP-VERIFICATION.md](DESKTOP-VERIFICATION.md) §6).
